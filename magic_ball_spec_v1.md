# Ask Sarcastic Magic Ball — Product Spec (MVP)

*(название рабочее — см. Open Questions: юридический риск ещё не проверен окончательно)*


## Problem Statement
Существующие приложения-шары для предсказаний раздражают пользователей частым бесполезным ответом ("Ask again later"), навязчивой рекламой и клишированным дизайном. При этом базовая механика (задать вопрос → получить случайный ответ) остаётся востребованной как лёгкое развлечение. Возможность выделиться — через характер (саркастичные, неожиданные ответы), приватность (вопрос не покидает устройство) и небанальный дизайн.

## Goals
1. Пользователь получает содержательный/забавный ответ при каждом обращении к шару — без пустых "спроси позже".
2. Взаимодействие ощущается персональным за счёт контекста устройства (время суток, заряд батареи, характер тряски).
3. Приложение не собирает и не передаёт никаких данных о вопросах пользователя.
4. Первое впечатление (запуск, визуал шара, анимация) не уступает по полировке платным конкурентам.

## Non-Goals (v1)
- **Аккаунты и история вопросов** — усложняет и противоречит принципу приватности.
- **AI-генерация ответов** — заранее написанный пул фраз даёт больше контроля над тоном и качеством юмора.
- **Android-версия** — не исключена в будущем (тот же веб-код), но не приоритет сейчас.
- **Мобильная обёртка (iOS/App Store)** — решение отложено, зависит от времени; веб-версия самодостаточна как MVP.
- **Монетизация** — добавится после того, как появятся живые пользователи.

## User Stories

**Основной сценарий:**
- Как пользователь, я хочу задать шару вопрос вслух и тряхнуть/тапнуть его, чтобы получить ответ — так же интуитивно, как с настоящим Magic 8 Ball.
- Как пользователь, я хочу видеть ответ, который явно относится к текущему моменту (например, ночью или при низком заряде), чтобы взаимодействие ощущалось "живым", а не рандомным генератором строк.
- Как пользователь, я хочу быть уверен, что вопрос, который я задаю вслух, нигде не записывается и не передаётся (приложение не запрашивает доступ к микрофону и не хранит историю), чтобы свободно спрашивать что угодно.

**Первый запуск:**
- Как новый пользователь, я хочу увидеть короткую атмосферную заставку при открытии приложения, чтобы сразу понять вайб продукта, пока он грузится.
- Как пользователь, я хочу увидеть краткую подсказку ("Ask your question out loud, then shake or tap the ball"), чтобы понять, что делать, без отдельного онбординга.

**Повторное использование:**
- Как пользователь, я хочу тапать шар повторно столько раз, сколько хочу, без ограничений и без надоедливых пауз между ответами.

## Requirements

### P0 (Must-Have)
| Требование | Критерий приёмки |
|---|---|
| Экран-заставка при запуске | Показывается минимум 1.5 секунды; если приложение грузится дольше — заставка держится, пока загрузка не завершится (что дольше из двух) |
| Экран с шаром | Шар кликабелен/тапабелен, есть анимация "тряски" перед ответом |
| Пул фраз с условиями показа | Ответ выбирается из фраз, подходящих под текущий контекст (`when to use`) + фразы с `anytime`; вес `anytime` вдвое выше остальных |
| Локальная обработка | Ни вопрос, ни какие-либо данные не отправляются на сервер; вся логика — на устройстве |
| Адаптивный текст ответа | Текст любой длины из пула корректно помещается в область "экрана" шара, без обрезки и без выхода за границы |
| Работает в браузере (desktop + mobile web) | Открывается и работает корректно на телефоне через браузер (не требует установки) |

### P1 (Nice-to-Have)
| Требование | Комментарий |
|---|---|
| Звук при появлении ответа | Один файл на первую версию; возможность разных звуков по категориям — заложена в структуру кода |
| Разные звуки/визуальные акценты по категориям фраз | Технически готово (SOUND_MAP_BY_CATEGORY), контент — по мере появления звуков |
| Вибрация при тряске шара | Через `navigator.vibrate()` — работает на Android (Chrome), **не работает в Safari на iOS** (ограничение самой платформы, не наше). На iOS заработает только через нативную обёртку (Capacitor), если до неё дойдём |

### P2 (Future Considerations)
- Мобильная обёртка (Capacitor) → публикация в App Store
- Монетизация (ненавязчивая реклама / IAP "remove ads")
- Тематические паки фраз (для вечеринок, для пар и т.д.)

## Acceptance Criteria (ключевой флоу)

- Given пользователь открывает приложение впервые
- When происходит запуск
- Then показывается заставка минимум 1.5 сек, затем — экран с шаром и подсказкой над ним

- Given пользователь на экране с шаром
- When тапает по шару
- Then шар "трясётся" ~0.6 сек → в треугольном окошке проявляется случайная подходящая по контексту фраза → фраза не обрезана и не выходит за границы окошка

- Given ответ уже показан
- When пользователь тапает шар снова
- Then предыдущий ответ исчезает, цикл повторяется без ограничений на количество попыток

## Success Metrics — не текущие данные, а определение "что значит успех"
Это не факты и не прогнозы — это то, по каким цифрам мы **в будущем** поймём, сработал продукт или нет (стандартная PM-практика: договориться о критериях заранее). В v1 эти метрики **не измеряются техническим — аналитики нет** (принцип приватности). Раздел документирует, что именно стоит начать отслеживать, если/когда добавим privacy-friendly инструмент (например, Plausible), не меняя принцип "вопрос не покидает устройство":

- **Activation**: % посетителей сайта, которые хотя бы раз тапнули шар
- **Engagement**: среднее число тапов за сессию
- **Retention**: % вернувшихся в течение 7 дней
