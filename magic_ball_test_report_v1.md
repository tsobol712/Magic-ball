# Test Report & Code Review — v0.1

Дата: перед первым деплоем на Vercel. Метод: ручное тестирование (заставка → шар не появлялся) + автоматизированное тестирование через headless-браузер (Playwright) — реальная загрузка собранного проекта, проверка DOM, консоли и скриншотов, а не чтение кода "на глаз".

## Баг №1 (найден пользователем в проде): чёрный экран после заставки

**Симптом**: после картинки с облаками — пустой чёрный экран вместо шара.

**Как локализовали**: подняли собранный проект локально, открыли в headless Chromium, сделали скриншот через 2.5 сек после загрузки и посмотрели HTML внутри `#root`. Заставка (`<div class="splash splash--fading">`) осталась в DOM — экран с шаром так и не смонтировался.

**Причина**: в `Splash.jsx` эффект, запускающий исчезновение заставки, был подписан на своё же состояние (`fadingOut`) в списке зависимостей. Когда состояние менялось, React пересоздавал тот же эффект — а пересоздание эффекта автоматически отменяет (`cleanup`) таймер из предыдущего запуска. В итоге таймер, который должен был через 400мс сообщить родителю "можно убирать заставку", отменялся раньше, чем успевал сработать. Ошибки в консоли при этом не было — с точки зрения JS всё "работало корректно", просто результат был неверный. Классическая ловушка `useEffect` + `setState` в зависимостях самого себя.

**Исправление**: убрали `fadingOut` из зависимостей эффекта, добавили `useRef` как флаг "уже запускали переход", не завязанный на ре-рендер. Эффект больше не пересоздаёт сам себя.

**Проверка**: пересобрали, прогнали тот же автоматический тест — заставка корректно исчезает, экран с шаром и подсказкой появляется, элементы найдены в DOM.

## Баг №2 (найден при автотестировании, не пользователем): "битые" мини-квесты в данных

**Симптом**: не проявлялся в ручном тестировании — обнаружили только при прогоне длинных фраз.

**Причина**: 24 из 364 строк в исходном экселе — это не единичные фразы-ответы, а **сценарии многошаговых мини-квестов**: с HTML-тегами `<br>`, ветвлением "если ДА / если НЕТ", таймингами показа ("через 400 ms:") и рабочими русскоязычными комментариями автора контента прямо внутри колонки Phrase. При случайном выборе такая "фраза" показалась бы пользователю как есть — с видимыми тегами и русским текстом вместо ответа.

**Временное исправление**: такие записи исключены из пула случайного выбора (по признаку наличия `<br>` в тексте) — работает по той же схеме, что уже была для неподключённых сенсоров (заряд батареи, сила тряски).

**Не исправлено полностью — открытый вопрос**: эти 24 сценария не удалены, а именно отложены — для них нужен отдельный UI (пошаговый показ, кнопки ДА/НЕТ, тайминги), а не место в общем пуле фраз. Это отдельная фича, не баг основного флоу.

- Случаев выхода текста за пределы области шара: **0**

## Известные ограничения (не баги, осознанные решения)
- Звук не работает, пока не загружен файл в `public/sounds/reveal.mp3` — ожидаемо.
- Вибрация не работает в Safari на iOS — ограничение платформы, не наше.
- Фразы с условием по заряду батареи / силе тряски не показываются — сенсоры ещё не подключены.
- 24 фразы-мини-квеста временно не в пуле — см. Баг №2.

## Вывод
Один баг, ушедший в прод, был не виден по коду при чтении "на глаз" — вскрылся только при реальной загрузке в браузере и проверке DOM, а не консоли (ошибок консоль не показывала). Второй баг вообще не проявился бы при ручном тестировании короткими фразами — только при систематическом прогоне по всему датасету. Отсюда практический вывод на будущее: **тестировать сборку в реальном браузере перед каждым деплоем**, а не полагаться на отсутствие ошибок в консоли как на признак "всё работает".
