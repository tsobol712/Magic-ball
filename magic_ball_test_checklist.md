# Test Checklist — Ask Sarcastic Magic Ball

Прогонять перед каждым деплоем на Vercel (после любых изменений в коде).

## Ручное тестирование (на реальном телефоне, не в превью чата)

- [ ] Заставка появляется сразу при открытии
- [ ] Заставка держится минимум ~1.5 сек
- [ ] Заставка корректно сменяется экраном с шаром (не зависает)
- [ ] Виден текст-подсказка над шаром
- [ ] Тап по шару запускает анимацию "тряски"
- [ ] После тряски появляется текст ответа
- [ ] Текст не обрезан и не выходит за границы фиолетового треугольника
- [ ] Текст читается — не слипается в один сплошной блок
- [ ] Повторный тап работает без ограничений, старый ответ корректно исчезает
- [ ] Не видно "сырых" технических символов в тексте (`<br>`, `undefined`, `NaN` и т.п.)
- [ ] Открыть ссылку заново (холодный старт) — заставка показывается снова

## Автоматическое тестирование (через Claude / headless-браузер)

- [ ] Собрать проект (`npm run build`) без ошибок
- [ ] Загрузить собранную версию в headless-браузер
- [ ] Подождать дольше, чем длится заставка — экран с шаром должен появиться в DOM
- [ ] Прогнать 30–40 тапов подряд, для каждого проверить:
  - [ ] нет ошибок в консоли браузера
  - [ ] в тексте ответа нет `<br>` / HTML-тегов
  - [ ] область текста не выходит за пределы шара
- [ ] Проверить самые длинные фразы из датасета отдельно (они первыми ломаются, если что-то не так с версткой)

## Что делать при находке бага
1. Зафиксировать точный шаг воспроизведения (что именно тапали/делали).
2. Проверить консоль браузера — есть ли явная ошибка, или баг "тихий" (как в Баге №1 из test-report — эффект без явной ошибки).
3. Если баг "тихий" — смотреть реальный DOM после события, а не полагаться на то, что код "выглядит правильно".
4. Исправить → пересобрать → прогнать чек-лист заново целиком, а не только тот пункт, что сломался (правки могут задеть соседнее).
